# 审计（Audit）

## 本技能解决什么

「做完了」是结论，不是感觉。审计阶段把结论变成证据：
逐条核对验收标准，留下结果与证据；偏差记录在案，不复盘不结束。

## 审计流程

1. 调用 `keel_spec`（模板 audit）生成 AUDIT.md；
2. 对照规格书（SPEC.md）的验收标准逐条核对，一行一条：
   - 结果：✅ 通过 / ❌ 未通过 / 跳过（跳过必须写理由）；
   - 证据：运行输出、测试结果、截图、命令记录；
3. 执行规格书「验证方法」小节中的每一条，不允许「目测通过」；
4. 记录偏差：未通过的验收标准、规格外实现的代码、未回填的假设；
5. 复盘三问：
   - 这次哪里最接近翻车？
   - 规格的哪个要素如果早写，能省多少时间？
   - 下轮最该删掉哪条守则的例外？
6. 用 `keel_review` 审查 AUDIT.md，确保记录本身合格。

## 偏差处置

| 偏差类型 | 处置 |
| --- | --- |
| 验收标准未通过 | 回到建造修复，或走变更单调整规格；两者都要留痕 |
| 规格外实现的代码 | 记录在案；要么补变更单追认，要么删除 |
| 未回填的假设 | 回填验证结论；[高] 假设未回填视为审计不合格 |
| 文档与实现不符 | 以验收标准为准修复文档，或走变更单改标准 |

原则：**偏差不可怕，追认才可怕**。任何偏差都必须有对应的记录，
不允许「先这样吧」式的口头豁免。

## 门禁

- AUDIT.md 存在 error 级发现 → 本轮不宣布完成；
- 存在未处置的 ❌ 验收标准 → 本轮不宣布完成；
- 全部通过 → 宣布完成，并把 AUDIT.md 与规格书一起归档。

## 审计的边界

- 审计不替代测试：审计核对「验收标准是否达成」，测试是验证方法的一部分；
- 审计不替代代码审查：代码质量发现记录为偏差，不在本轮顺手重构；
- 审计产出是下一轮锚定的输入：复盘结论直接进入下一份规格的「边界」。

## 常见错误

- 审计时只填结果不填证据：没有证据的结果是愿望；
- 用「用户不会遇到」为未通过项开脱：未通过就是未通过，处置方式见上表；
- 复盘流于表扬与检讨：复盘必须产出「下轮规格里新增的边界」或「删除的守则例外」。
