# 规格书：todo-cli 待办清单工具

> 本文件由 keel 生成。填写全部字段后运行 keel_review，错误清零前禁止进入建造。

## 目标

当用户运行 todo 命令时，系统提供添加、完成、列出、删除四种操作，操作结果写入当前目录的 todo.json 文件，进程退出后数据保留。

## 边界

**范围内**

- 添加、完成、列出、删除四种命令操作
- 数据持久化到当前目录的 todo.json
- 对不存在的编号给出错误提示

**范围外（明确不做的）**

- 不提供子任务与优先级字段
- 不提供到期提醒与日历集成
- 不提供多用户与权限控制
- 不提供云同步与远程存储

## 需求

- R-01 添加操作：`todo add <内容>` 将一条待办追加到列表，输出「已添加 #编号」。
- R-02 完成操作：`todo done <编号>` 将指定编号的待办标记为已完成，输出「已完成 #编号」。
- R-03 列出操作：`todo list` 按编号升序输出全部待办，未完成项标记 [ ]，已完成项标记 [x]。
- R-04 删除操作：`todo remove <编号>` 移除指定编号的待办，输出「已删除 #编号」。
- R-05 数据存储：列表持久化到当前目录的 todo.json，文件不存在时首次写入自动创建。
- R-06 编号规则：编号从 1 开始递增，删除后不重用，追加新项取当前最大编号加一。

## 验收标准

- AC-01 执行 `todo add 购物` 后执行 `todo list`，输出包含一条 [ ] 状态的「购物」。
- AC-02 执行 `todo add 购物` 后执行 `todo done 1`，`todo list` 输出该条为 [x] 状态。
- AC-03 执行 `todo remove 1` 后，`todo list` 不再输出编号 1 的条目。
- AC-04 连续添加三条后退出进程，再次运行 `todo list` 仍输出三条。
- AC-05 对编号 99 执行 done 与 remove，输出错误消息「编号不存在」，列表不变。
- AC-06 todo.json 为 JSON 数组，元素含 id、content、done 三个字段。

## 验证方法

- 在临时目录执行 npm test（测试用例覆盖 AC-01 至 AC-06）。
- 手工冒烟：依次运行 add、list、done、list、remove、list 六个命令，对照 AC-01 至 AC-04。
- 边界检查：对编号 99 运行 done 与 remove，对照 AC-05。
- 文件检查：运行后打开 todo.json，对照 AC-06。
